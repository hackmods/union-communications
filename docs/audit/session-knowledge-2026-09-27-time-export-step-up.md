# Workforce Time report export fresh MFA step-up — 2026-09-27

## Scope and outcome

The Time module exposes confidential union/local work-hour records as CSV,
XLSX, and PDF. `GET /api/time/export` previously generated and returned those
files with query-string filters. It is now retired with `405 Method Not
Allowed`; `POST /api/time/export` is the only download path.

The route requires an authenticated Time administrator, validates the format,
date range, and category, and applies every list filter through the actor's
union/local session scope. The shared fresh-MFA helper runs before the route
reads time entries. When the host MFA policy is disabled in non-hosted
installations, the helper preserves that operator-selected behavior.
UnionOps-operated customer mode is expected to configure production TOTP and
fails closed if that profile is missing.

The request can include `mfaCode` in its JSON body. The dashboard makes the
initial POST without the code, then displays a localized step-up form on the
server's `428` response. The exact selected format and date range stay in
component state through verification; changing the date inputs does not
silently change an already-pending export. The response is private/no-store.

The audit event records the actor, union/local, format, optional category,
row count, outcome, and server-generated request ID. It excludes the challenge
code and time-entry contents. Denied, throttled, generation-error, and
successful attempts are recorded. A successful audit append must complete
before the generated bytes are returned; if the audit store is unavailable,
the route withholds the file and responds with
`503 export_audit_unavailable`.

## Tests added

`src/app/api/time/export/route.test.ts` covers direct API challenge denial
before row access, MFA rate limiting without challenge-code logging, tenant
scope and filter propagation, correlated success audit and private response,
fail-closed behavior when the success audit cannot be written, and retirement
of the legacy GET route. The existing
`src/lib/time/pto-sites-export-routes.test.ts` retains an integration case that
checks local-only CSV results and now asserts the old GET path returns 405.

## Decisions and limits

- The route calls the shared MFA policy so self-hosted operators keep their
  configured MFA behavior; hosted customer readiness remains responsible for
  enforcing `UNIONOPS_HOSTED_CUSTOMER_MODE=true` and production TOTP.
- The audit append occurs after file generation but before delivery. This
  avoids reporting a delivered file without a confirmed success record, though
  generation can still consume CPU before an audit outage is discovered.
- The GET path has no compatibility redirect because query-string downloads
  would allow clients to reach the old download behavior without the same-
  request challenge contract.
- The API route tests are authored, but this checkout has no installed
  `node_modules`; Vitest, TypeScript, lint, browser download checks, and hosted
  Postgres/RLS/TOTP/audit verification remain pending.
