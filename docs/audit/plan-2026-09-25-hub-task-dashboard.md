# Officer Hub home: UX audit and implementation plan — 2026-09-25

**Baseline:** latest `main` at `f4988ed0`. Authenticated with the seeded Local 777 president through the repo demo login. Full page captures: [phone](hub-before-375.png) and [desktop](hub-before-1280.png). The public login page was not used as a dashboard reference.

## Findings

1. **Attention is buried.** At 1280 × 900 the H1 starts at 320 px, the static “Today” shortcuts at 434 px, setup at 639–1227 px, Officer tools at 1395 px, modules at 2337 px, and personal tasks/check-ins only after the module grid. At 375 px, three persistent notices and the Hub bar put the H1 at 571 px; the first screen has no actual assigned work.
2. **Five surfaces repeat navigation.** `HubNav` contains modules and grouped tools. `PresidentTodayStrip`, the setup card, checklist, `HubOfficerToolsCatalog`, and the module grid repeat links. “Today” has no live counts; its label implies a status it cannot establish. Wide layouts spend their width on four equal tool columns and a long scroll rather than a work area.
3. **Status can be misleading.** `MyTasksWidget` treats a failed response as an empty list; `MyCheckinsWidget` disappears when empty. Both rely on a seed fallback rather than the live tenant. The checklist treats grievance plus Portal as mandatory, a browser-local configuration visit as durable progress, and a hardcoded `caat-s-ft` English snippet result as readiness. Seeded snippets can make that step “done” without a local officer preparing anything.
4. **Security is partly in place.** The app page redirects members to Portal; module/tool catalogs filter by role and enabled modules; API routes retain their own checks. The dashboard must keep those gates, the active union/local context, the host MFA policy, invite-only entry, and the existing notices. Platform admin operations must remain visibly distinct from local casework.

## Plan

1. Put a compact identity line and an **Attention** work area directly under the heading. Move tasks and unanswered check-ins here, with explicit loading, empty, and error states. Give an MFA-locked visitor one clear verification action. If neither module is enabled, say so without implying there is no other work.
2. Add a **Next steps** area of a few role-permitted links. Use the existing module registry and tool-access model; president suggestions can include overdue, meetings, Portal, and local setup only when allowed. Keep platform operations in their own card, ahead of local suggestions. Keep the global nav for wayfinding.
3. Replace the president checklist and setup card with one compact, advisory setup surface. Do not count browser visits, default module choices, or seeded snippets as completed work. Link to the CA library only when grievance is enabled. Keep the full officer-tools catalog as optional discovery below the work area; replace the duplicate module grid with a small module index or remove it if the nav/catalog covers all routes.
4. Compose desktop as a wide work column and narrower next-step rail; on mobile keep attention first and discovery last. Make operational notices concise on this route while retaining their full meaning and access to detail. Keep other module pages’ chrome intact.
5. Add role/MFA/module/browser tests, review EN/FR at 375, 768, 1280, 1536, and 1920 px, including keyboard/reflow/contrast/reduced motion. Run lint, typecheck, unit, focused browser, and relevant smoke suites; record unrelated failures. Update Progress and What’s new, commit, open a ready PR, and follow the repository merge rule.

**Boundary:** no casework route, adapter, tenant query, security policy, or public Hub signup change.

## Implementation and verification

- The dashboard now places assigned tasks and unanswered check-ins beside role-permitted next steps. Platform administrators get host operations instead of local case suggestions. A configured MFA lock replaces private summaries and secondary links with one verification path. When tenant settings are not available, the dashboard waits instead of inventing enabled modules.
- The president setup surface is advisory and appears after the work area. It has no progress count; Portal and CA-library links respect the enabled modules. The hardcoded `caat-s-ft` request and browser-local “configuration visited” marker are gone. The full officer-tools catalog is an optional disclosure; module navigation stays in the Hub bar/drawer.
- On the dashboard only, demo, early-access, and temporary-storage notices share a short visible warning with expandable full text. The meeting reminder remains independent. The Hub bar uses its accessible drawer below 1536 px on this route, avoiding multi-row French module navigation.
- Final authenticated captures: [English phone](hub-after-en-375.png), [English desktop](hub-after-en-1280.png), [French phone](hub-after-fr-375.png), [French desktop](hub-after-fr-1280.png). At 1280 × 900 the attention heading moved from below the long catalog to about **391 px**; at 375 × 900 it starts near **358 px**, with the task card visible in the first viewport. EN/FR reflow at 375, 768, 1280, 1536, and 1920 px had no horizontal page overflow.
- Typecheck passed. Full lint passed with two warnings already present in unrelated customization files. Full unit suite passed: **2,457 passed, 1 skipped**. Focused Hub browser checks cover president, steward, member redirect, empty versus failed fetch, keyboard drawer/focus, EN/FR reflow, reduced motion, forced colours, and axe colour contrast; configured-MFA lock/unlock passed on an MFA-enabled local host. The broader Hub mobile/org smoke set passed 43 checks; its one failure was an outdated assertion for the removed module grid, which was updated and passed in the focused rerun.
- `npm run test:smoke` was started but stopped after an unrelated Brand Kit reset-dialog failure in the parallel run (43 of 337 cases reached). The same Brand Kit case passed when rerun alone. The directly relevant Hub smoke checks were run separately. A real screen reader and a browser control set to 200% zoom remain manual checks; automated 640 CSS-pixel reflow approximated 1280 px at 200% zoom.
